# 기능 03. 게시물 상세와 반응

## 기능 목표

하나의 게시물을 가장 깊게 소비하고 반응할 수 있는 핵심 화면을 만든다.

## 사용자 흐름

1. 사용자가 `/p/[postId]`를 연다.
2. 전체 이미지, 작성자 정보, 캡션, 댓글 목록을 본다.
3. 좋아요를 토글하거나 댓글을 제출한다.
4. 화면 맥락을 잃지 않고 결과가 갱신된다.

## UI 범위

- 큰 게시물 미디어 영역
- 작성자 요약 행
- 캡션 블록
- 좋아요 수
- 댓글 목록
- 댓글 작성 폼

## 기능 구현

- 게시물 하나를 충분한 맥락과 함께 보여준다.
- 좋아요 토글을 지원한다.
- 댓글 작성 기능을 지원한다.
- 작성자 이름과 아바타는 프로필 페이지로 연결한다.

## 구현 로직

1. `app/(main)/p/[postId]/page.tsx`가 서버에서 게시물 id로 데이터를 조회한다.
2. `lib/queries/post.ts`는 게시물, 작성자, 댓글, 현재 사용자 반응 상태를 함께 반환한다.
3. `components/post/post-detail.tsx`가 페이지 셸을 렌더링한다.
4. `components/post/post-actions.tsx`는 좋아요 토글을 담당하는 클라이언트 컴포넌트다.
5. `components/post/comment-form.tsx`는 `lib/actions/interaction.ts`의 Server Action으로 댓글을 제출한다.
6. 댓글 액션은 길이와 빈 입력을 검증한 뒤 댓글을 생성하고 현재 게시물 경로를 재검증한다.
7. 체감 품질을 위해 댓글 제출은 `useActionState`, 좋아요는 `useOptimistic`을 적용할 수 있다.

## 상태관리

- 게시물 데이터: 서버
- 좋아요 상태: 로컬 낙관적 클라이언트 상태
- 댓글 폼 상태: `useActionState`

## 필요한 데이터

- 게시물 레코드
- 작성자 레코드
- 댓글 목록
- 현재 사용자의 좋아요 여부

## 완료 기준

- 피드와 프로필에서 상세로 진입할 수 있다.
- 좋아요가 동작한다.
- 댓글이 검증과 함께 등록된다.
- 댓글이 없을 때도 페이지가 깨지지 않는다.

## MVP 제외 범위

- 대댓글
- 댓글 수정과 삭제
- 저장, 공유
- 신고나 모더레이션 흐름
- 모달형 라우트 인터셉트

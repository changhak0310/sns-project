# 기능 04. 게시물 작성

## 기능 목표

로그인한 사용자가 최소한의 마찰로 게시물을 올릴 수 있게 해서 사용자 루프를 닫는다.

## 사용자 흐름

1. 사용자가 `/create`에 진입한다.
2. 1차 구현 방식에 맞춰 이미지 프리셋을 선택하거나 제한된 이미지 소스를 입력한다.
3. 캡션을 작성한다.
4. 폼을 제출한다.
5. 새 게시물 상세나 프로필 페이지로 이동한다.

## UI 범위

- 미디어 선택 영역
- 캡션 textarea
- 글자 수 피드백
- 제출 버튼과 pending 상태
- 성공 후 리다이렉트

## 기능 구현

- 제작 속도를 우선하는 작성 폼으로 설계한다.
- 1차 구현은 실제 업로드 도구보다 프리셋 이미지 라이브러리나 제한된 이미지 소스 전략을 우선한다.
- 실제 바이너리 업로드는 1차를 막는 필수 조건이 아니라 확장 목표로 둔다.

## 구현 로직

1. `app/(main)/create/page.tsx`가 작성 페이지를 렌더링한다.
2. `components/post/create-post-form.tsx`가 상호작용 폼을 담당한다.
3. `lib/actions/post.ts`에 `createPostAction`을 둔다.
4. `createPostAction`은 선택된 이미지 소스와 캡션 길이를 검증한다.
5. 액션은 저장소 계층을 통해 새 게시물을 만들고 `/p/[postId]` 또는 `/u/[username]`으로 리다이렉트한다.
6. 1차가 프리셋 기반이면 폼은 실제 파일 대신 `imageId`를 제출한다.
7. 이후 실제 업로드를 추가할 때는 페이지 계약을 바꾸지 않고 스토리지 어댑터나 `route.ts` 업로드 엔드포인트만 확장한다.

## 상태관리

- 폼 드래프트: 로컬 컴포넌트 상태
- 제출 에러: `useActionState`
- 생성된 게시물 데이터: 액션 이후 서버가 권한을 가진다

## 필요한 데이터

- 세션의 작성자 id
- 선택된 이미지 참조값
- 캡션 텍스트

## 완료 기준

- 사용자가 UI에서 게시물을 만들 수 있다.
- 빈 제출이나 잘못된 입력이 검증된다.
- 성공 후 사용자가 결과를 볼 수 있는 화면으로 이동한다.
- 저장소 동작에 따라 새 게시물이 피드와 프로필에 반영된다.

## MVP 제외 범위

- 멀티 이미지 업로드
- 이미지 크롭
- 필터 편집기
- 위치 태그
- 영상 또는 릴스 작성

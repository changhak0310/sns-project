# 기능 01. 인증과 온보딩

## 기능 목표

사용자를 최대한 빠르게 서비스 안으로 들여보내되, 인증 영역과 비인증 영역을 명확히 나눈다.

## 사용자 흐름

1. 사용자가 `/login`에 진입한다.
2. 데모 계정을 선택하거나 간단한 로그인 폼을 제출한다.
3. 서버가 요청을 검증하고 세션을 만든다.
4. 사용자는 `/`로 리다이렉트된다.
5. 세션이 없으면 보호된 라우트는 `/login`으로 되돌아간다.

## UI 범위

- 로그인 페이지
- 데모 계정 카드 또는 간단한 로그인 폼
- 제출 중 상태와 에러 상태
- 메인 앱 셸의 로그아웃 액션

## 기능 구현

- 진입 장벽이 낮은 로그인 UI를 제공한다.
- 데모와 테스트를 위해 원클릭 데모 로그인 방식을 지원한다.
- 메인 라우트는 모두 세션 체크 뒤에 둔다.
- 로그아웃은 공통 헤더나 프로필 영역에서 노출한다.

## 구현 로직

1. `app/(auth)/login/page.tsx`에서 로그인 화면을 렌더링한다.
2. `components/auth/login-form.tsx`가 클라이언트 폼 UI를 담당한다.
3. `lib/actions/auth.ts`에 `loginAction`, `logoutAction`을 Server Action으로 정의한다.
4. `loginAction`은 입력값을 검증하고, 선택된 데모 유저를 해석한 뒤 세션 쿠키를 만들고 `/`로 리다이렉트한다.
5. `app/(main)/layout.tsx`는 서버에서 현재 세션을 확인하고, 없으면 `/login`으로 보낸다.
6. `logoutAction`은 세션을 비우고 `/login`으로 리다이렉트한다.

## 상태관리

- 검증 에러: `useActionState`
- 제출 중 상태: action pending state
- 세션 상태: 서버 쿠키와 세션 helper

## 필요한 데이터

- 데모 유저 목록
- `userId`, `username`을 담는 세션 payload

## 완료 기준

- 사용자가 `/login`에서 로그인할 수 있다.
- 세션이 없으면 보호 라우트를 열 수 없다.
- 로그아웃이 안정적으로 동작한다.
- 잘못된 입력에 대해 에러 메시지가 보인다.

## MVP 제외 범위

- OAuth
- 비밀번호 재설정
- 이메일 인증
- 멀티 계정 전환

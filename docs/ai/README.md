# AI 문서 가이드

## 1. 문서 목적

이 문서는 프로젝트에서 사용하는 AI 관련 문서의 위치, 역할, 작성 규칙을 정리한다.
AI 프롬프트 문서를 목적별로 분리하고, 구현 및 리뷰 과정에서 어떤 기준 문서를 다시 확인해야 하는지 명확히 유지하는 것을 목표로 한다.

## 2. 디렉터리 구조

```text
docs/
  ai.md
  prompts/
    base-agent.md
    code-review-agent.md
    logging-rules.md
```

- `prompts/`: AI 에이전트별 프롬프트 문서와 공통 규칙 문서를 관리한다.

## 3. 문서 목록

### `prompts/base-agent.md`

- 기본 개발 작업용 AI 에이전트 프롬프트 문서
- 구현 시작 전뿐 아니라 구현 중에도 필요 시 설계 문서와 기능 문서를 다시 확인하는 규칙을 포함한다.

### `prompts/code-review-agent.md`

- 코드 리뷰용 AI 에이전트 프롬프트 문서
- 변경 사항의 위험 요소, 회귀 가능성, 테스트 누락 여부를 우선 확인하는 리뷰 기준을 담는다.

### `prompts/logging-rules.md`

- AI 작업 및 리뷰 로그의 공통 작성 규칙 문서
- 로그 형식, 기록 범위, 공통 표기 규칙을 일관되게 유지하기 위한 기준 문서다.

## 4. 작성 규칙

- 새 AI 문서는 목적별로 `prompts/` 아래에 추가한다.
- 문서 파일은 `*.md` 확장자를 사용한다.
- 파일명은 역할이 드러나도록 일관되게 작성한다.
- 공통 규칙은 여러 프롬프트에 중복 작성하지 말고 별도 문서로 분리한다.

## 5. 베이스 에이전트 참조 규칙

- `base-agent.md`를 사용하는 AI는 구현 전에 관련 설계 문서와 기능 문서를 먼저 확인해야 한다.
- 구현 중에도 요구사항 해석, 화면 구조, 데이터 흐름, 예외 처리 기준을 다시 점검할 필요가 생기면 관련 문서를 다시 확인해야 한다.
- 과거 표현으로 `doc/설계도/`, `doc/기능/`을 사용할 수 있지만, 현재 저장소에서는 아래 경로를 기준으로 해석한다.

### 설계 문서 기준

- `docs/architecture.md`
- 필요 시 전반 계획 문서인 `docs/project-plan.md`

### 기능 문서 기준

- `docs/features/`
- 상세 구현 흐름 확인이 필요하면 `docs/plan/`

## 6. 운영 원칙

- AI 문서는 구현 문서와 분리하되, 프로젝트 문서 체계 안에서 함께 관리한다.
- 프롬프트 문서가 특정 구현 규칙을 참조할 때는 실제 저장소 경로를 기준으로 작성한다.
- 문서 구조가 바뀌면 `ai.md`와 관련 프롬프트 문서도 함께 갱신한다.

# 인스타 분석과 MVP 방향

## 1. 왜 인스타형 SNS가 이번 프로젝트에 맞는가

- 이미지 중심 서비스라서 디자인 완성도가 바로 드러난다.
- 사용자 흐름이 짧고 닫혀 있다. 피드 확인 -> 반응 -> 작성 -> 프로필 회귀 흐름이 명확하다.
- Next.js 강점과 잘 맞는다. 라우트 기반 화면 구성, 메타데이터, 이미지 처리, 동적 프로필 라우팅이 자연스럽다.
- 기능을 줄여도 서비스 정체성이 유지되어 완성도 확보에 유리하다.

## 2. 반드시 살려야 하는 인스타 핵심 루프

1. 사용자가 빠르게 로그인한다.
2. 개인화된 피드에 도착한다.
3. 게시물을 열고 좋아요나 댓글로 반응한다.
4. 직접 게시물을 작성한다.
5. 프로필에서 자신의 아카이브를 다시 확인한다.

이 루프가 중요한 이유는, 단순한 화면 모음이 아니라 하나의 서비스 경험으로 보이게 만들기 때문이다.

## 3. 인스타답게 느껴지는 핵심 요소

### 반드시 포함할 요소

- 이미지 중심의 강한 시각 계층
- 모든 게시물에 붙는 작성자 정체성
- 피드 카드에서 상세 페이지로 이어지는 흐름
- 좋아요와 댓글 반응
- 프로필 헤더와 그리드 아카이브
- 짧은 캡션 기반의 스토리텔링

### 시간이 남으면 추가할 요소

- 피드 카드 내 댓글 미리보기
- 프로필의 팔로우 버튼
- 간단한 상대 시간 표기
- 신규 사용자용 빈 상태 화면

### 이번 마감에서는 과감히 제외할 요소

- 스토리
- 릴스 또는 영상 편집
- DM
- 푸시 알림
- 멀티 이미지 캐러셀
- 탐색 랭킹 알고리즘
- 저장 컬렉션
- 라이브 커머스, 광고, 태그, 신고 기능

핵심 기준은 단순하다. 닫힌 사용자 흐름을 강화하지 않는 기능은 MVP에서 제외한다.

## 4. 추천 MVP 범위

최종 MVP는 아래 다섯 기능에 집중하는 것이 가장 좋다.

1. 인증과 데모 온보딩
2. 홈 피드
3. 게시물 상세와 반응
4. 게시물 작성
5. 프로필과 팔로우

이 정도면 "인스타 같은 SNS"라는 인상을 충분히 주면서도 마감 전 완성 가능성이 높다.

## 5. 빠르지만 완성도 있게 만드는 전략

### 제품 포지셔닝

- 폐쇄형 데모 SNS
- 운영형 서비스가 아니라 포트폴리오 품질의 제품 데모
- AI-assisted 디자인 시스템이 실제 서비스 표면에 적용된 결과물

### 범위 결정 원칙

- 넓은 기능 범위보다 매끄러운 흐름을 우선한다.
- 어설픈 화면 세 개보다 끝까지 닫히는 라우트 하나가 낫다.
- 1차는 시드 데이터와 저장소 추상화로 빠르게 만들고, 시간이 남으면 영속성을 확장한다.

## 6. AI-assisted 디자인 시스템 연결 방식

이번 프로젝트는 AI를 단순한 코드 생성기가 아니라 디자인 파트너로 설명할 때 더 설득력이 있다.

### AI가 도와야 하는 영역

- 컨셉 키워드 정리
- 무드보드 방향 탐색
- 컬러 토큰 탐색
- 타이포그래피 조합 아이디어
- 시드용 캡션, 바이오, 데모 콘텐츠 작성
- 온보딩과 빈 상태용 UI 카피 변주

### AI가 주도하면 안 되는 영역

- 핵심 정보 구조
- 최종 기능 범위 결정
- 데이터 모델 경계
- 접근성과 반응형 마감 품질

## 7. 이 범위가 설득력 있는 이유

- 단순한 UI 조각이 아니라 서비스 설계 능력을 보여준다.
- 디자인 시스템이 컴포넌트 모음으로 끝나지 않고 실제 제품에 적용된다.
- Next.js의 장점이 잘 드러난다. 레이아웃, 메타데이터, 이미지 중심 UI, 동적 라우팅을 모두 활용할 수 있다.
- 작지만 끝낼 수 있는 범위라서 발표와 데모에서 자신감이 생긴다.

## 8. 최종 권장안

아래 흐름이 완성되는 인스타형 SNS를 만든다.

1. 로그인한다.
2. 피드를 본다.
3. 게시물을 연다.
4. 좋아요나 댓글을 남긴다.
5. 캡션이 있는 게시물을 작성한다.
6. 프로필 그리드를 확인한다.
7. 다른 사용자를 팔로우한다.

그 외 기능은 1차 빌드가 안정화된 뒤에만 확장 목표로 본다.

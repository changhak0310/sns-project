## 작업: logout 서버 기능 구현

### 작업 시간
- 2026-04-11 17:04

### 요청 요약
- `docs/plan/function/mvp-1/03-logout.md`를 기준으로 로그아웃 기능의 서버 구현을 추가한다.

### 합의된 범위
- 로그아웃 명세에 있는 `POST /api/auth/logout` route handler를 구현한다.
- 현재 앱에 실제 세션 저장소가 없는 점을 고려해, 서버는 세션 쿠키 정리와 응답 계약 유지에 집중한다.
- 회귀 방지를 위한 서버 계약 테스트와 작업 로그를 함께 추가한다.

### 참고 문서
- `docs/plan/function/mvp-1/03-logout.md`
- `docs/ai/prompts/base-agent.md`
- `docs/ai/prompts/logging-rules.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/cookies.md`

### 반영 내용
- `app/api/auth/logout/route.ts`를 추가해 `POST /api/auth/logout` route를 구현했다.
- Next.js `cookies()` API를 사용해 `orbit-session` 쿠키를 삭제하고, 성공 시 `{ success: true }`를 반환하도록 맞췄다.
- 실패 응답은 명세의 로그아웃 처리 실패 메시지와 서버 오류 메시지를 분리해 `createFailureResponse()`로 정규화했다.
- `__tests__/auth/logout-server-contract.test.js`를 추가해 logout route 존재, `next/headers` 사용, body 없는 요청 처리, 성공/실패 응답 계약을 고정했다.

### 검증
- `npm run lint` 통과
- `npm test` 통과
- `npm run build` 통과

### 결과 또는 기대 효과
- 클라이언트 `authRepository.logout()`가 호출하는 `/api/auth/logout` 서버 엔드포인트가 실제로 동작한다.
- 향후 로그인 서버가 동일한 세션 쿠키를 발급하게 되면 현재 로그아웃 route와 바로 연결할 수 있다.
- logout 서버 계약이 테스트로 고정돼 이후 인증 작업에서 회귀를 줄일 수 있다.

### 후속 메모
- 현재 로그인 route는 세션 쿠키를 발급하지 않으므로 logout은 쿠키 삭제 중심의 noop-safe 구현이다.
- 실제 세션 유지가 필요해지면 로그인/로그아웃에서 공유하는 세션 토큰 저장 정책을 별도 서버 계층으로 분리하는 것이 다음 단계다.

## 작업: post management 컴포넌트 구현

### 작업 시간
- 2026-04-11 17:12

### 요청 요약
- `docs/plan/function/mvp-1/04-post-management.md`를 기준으로 게시글 작성/수정/삭제 기능의 컴포넌트 계층을 구현한다.

### 합의된 범위
- `CreatePostPage`, `EditPostPage`, `PostComposerForm`, `PostCard`, `PostActionMenu`를 포함한 컴포넌트 세트를 feature 계층에 추가한다.
- 현재 route-design 문서에 전용 post edit 경로가 없으므로 `/create`는 실제로 연결하고, edit page는 컴포넌트만 준비한다.
- 타입, 프리뷰용 seed 데이터, 계약 테스트, 작업 로그를 함께 추가한다.

### 참고 문서
- `docs/plan/function/mvp-1/04-post-management.md`
- `docs/plan/layout/project-structure.md`
- `docs/plan/layout/route-design.md`
- `docs/plan/layout/design-system.md`
- `docs/plan/layout/design-system/screen-patterns.md`
- `docs/plan/layout/design-system/components-ui.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/page.md`

### 반영 내용
- `types/post-management.ts`에 post management 전용 타입과 컴포넌트 계약을 정리했다.
- `data/seed/posts.ts`에 create/edit/card 프리뷰에 사용할 게시글 seed 데이터를 추가했다.
- `features/post-management/components` 아래에 `PostComposerForm`, `PostImagePicker`, `CaptionInput`, `PostPreview`, `CreatePostSubmitButton`, `EditPostSubmitButton`, `PostFormErrorMessage`, `PostCard`, `PostActionMenu`, `EditPostLinkButton`, `DeletePostButton`, `PostActionErrorMessage`, `CreatePostPage`, `EditPostPage`를 추가했다.
- `app/(main)/create/page.tsx`를 실제 `CreatePostPage`를 렌더링하는 route leaf로 교체했다.
- `CreatePostPage` 오른쪽 영역에 `PostCard`와 `PostActionMenu` 프리뷰를 같이 배치해서 card/action menu 컴포넌트도 바로 확인할 수 있게 했다.
- `EditPostPage`는 feature 계층에 구현했지만, route-design 문서에 전용 post edit 경로가 정의되지 않아 이번 단계에서는 라우트로 연결하지 않았다.
- `__tests__/post-management/post-management-components-contract.test.js`를 추가해 핵심 파일 존재, `/create` 연결, composer/action menu 조합 계약을 고정했다.

### 검증
- `npm run lint` 통과
- `npm test` 통과
- `npm run build` 통과

### 결과 또는 기대 효과
- `/create`에서 더 이상 공통 기반 플레이스홀더가 아니라 실제 게시글 작성용 컴포넌트 조합을 확인할 수 있다.
- post management의 작성/수정 래퍼와 카드 액션 메뉴가 feature 경계 안에 정리돼 후속 hook/service/repository/server 단계에서 교체 범위를 줄일 수 있다.
- post edit route가 합의되면 `EditPostPage`를 그대로 연결할 수 있는 상태가 된다.

### 후속 메모
- 현재 submit/delete는 컴포넌트 단계의 로컬 시뮬레이션이다. 후속 단계에서 hook/service로 대체해야 한다.
- post edit 라우트는 route-design 문서 합의가 먼저 필요하다.

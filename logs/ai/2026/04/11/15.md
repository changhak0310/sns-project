## 작업: 로그인 명세 기반 컴포넌트 구현

### 작업 시각
- 2026-04-11 15:29

### 요청 요약
- `docs/ai/README.md`와 베이스 에이전트 규칙을 따르면서 `docs/plan/function/mvp-1/02-login.md` 명세 기반으로 로그인 기능 컴포넌트를 구현한다.

### 합의된 범위
- `LoginForm`을 명세형 상태 기반 컴포넌트로 교체한다.
- 로그인 버튼/에러 컴포넌트, `useLogin`, `loginService`, repository 확장, 공통 타입 계약을 추가한다.
- 기존 인증 레이아웃과 현재 디자인 시스템 프리뷰가 깨지지 않도록 최소 범위로 연결한다.

### 참고 문서
- `docs/ai/README.md`
- `docs/ai/prompts/base-agent.md`
- `docs/ai/prompts/logging-rules.md`
- `docs/plan/function/mvp-1/02-login.md`
- `docs/plan/layout/architecture.md`
- `docs/plan/layout/project-structure.md`
- `docs/plan/layout/design-system/auth-login.md`
- `node_modules/next/dist/docs/01-app/01-getting-started/05-server-and-client-components.md`

### 반영 내용
- `features/auth/components/login-form.tsx`를 정적 프리뷰 폼에서 `useLogin()` 기반의 실제 상태형 폼으로 교체했다.
- `features/auth/components/login-submit-button.tsx`, `login-error-message.tsx`를 추가해 로그인 전용 제출/에러 표현을 분리했다.
- `features/auth/hooks/use-login.ts`를 추가해 이메일, 비밀번호, 실시간 검증 메시지, 제출 상태, 로그인 결과 상태를 관리하도록 구현했다.
- `features/auth/services/login-service.ts`를 추가해 입력 검증과 로그인 요청 흐름을 `LoginForm`에서 분리했다.
- `lib/social-repository/auth-repository.ts`에 `login()`을 추가하고 응답 파서를 로그인/회원가입 공용 구조로 정리했다.
- `types/auth.ts`에 로그인 상태, 액션, 결과 타입과 인증 공용 props 계약을 추가했다.
- `features/auth/components/email-input-field.tsx`, `password-input-field.tsx`를 로그인/회원가입 공용 필드로 재사용할 수 있게 정리했다.
- `features/design-system/components/design-system-showcase.tsx`의 `LoginForm` 사용부를 현재 인터랙티브 폼 구조에 맞게 수정했다.

### 검증
- `npm run lint`
- `npm test`
- `npm run build`

### 결과 또는 기대 효과
- `/login` 경로가 더 이상 플레이스홀더가 아니라 명세에 맞는 실제 입력/검증/제출 구조를 가진 로그인 폼을 렌더링한다.
- 로그인 검증 규칙과 API 호출 경계가 컴포넌트에서 분리되어 이후 세션 저장, 서버 액션, API 연동 단계로 확장하기 쉬워졌다.
- 기존 회원가입 구현과 동일한 `hook -> service -> repository` 구조로 인증 기능 계층이 정리되었다.

### 남은 이슈
- `/api/auth/login` 서버 구현과 세션 저장 로직은 아직 없으므로 성공 후 리다이렉트/세션 연결은 후속 작업이 필요하다.
- 기존 워크트리에 있던 `README.md`, `package.json`, `scripts/` 변경은 이번 범위와 무관해 그대로 유지했다.

## 작업: 로그아웃 명세 기반 셸 액션 구현

### 작업 시각
- 2026-04-11 15:43

### 요청 요약
- `docs/ai/README.md`와 베이스 에이전트 규칙을 따르면서 `docs/plan/function/mvp-1/03-logout.md` 명세 기반으로 로그아웃 기능 컴포넌트를 구현한다.

### 합의된 범위
- 공통 셸에서 로그인 버튼 또는 프로필/로그아웃 액션을 노출하는 `AuthActionArea`를 추가한다.
- `useLogout`, `logoutService`, `authRepository.logout()`을 추가해 로그아웃 요청 흐름을 분리한다.
- 전역 세션 사용자 상태를 공유할 최소 `SessionProvider`를 추가하고, 메인 셸이 이 값을 읽어 반응하도록 연결한다.

### 참고 문서
- `docs/ai/README.md`
- `docs/ai/prompts/base-agent.md`
- `docs/ai/prompts/logging-rules.md`
- `docs/plan/function/mvp-1/03-logout.md`
- `docs/plan/function/mvp-1/09-session-guard-navigation.md`
- `docs/plan/layout/architecture.md`
- `docs/plan/layout/project-structure.md`
- `docs/plan/layout/route-design.md`
- `docs/plan/layout/design-system.md`
- `docs/plan/layout/design-system/components-layout.md`
- `docs/plan/layout/design-system/components-ui.md`
- `node_modules/next/dist/docs/01-app/03-api-reference/04-functions/use-router.md`

### 반영 내용
- `lib/session/session-provider.tsx`, `lib/session/session-reducer.ts`를 추가해 `SessionProvider + reducer/context` 기반의 최소 전역 세션 상태를 만들고 `app/layout.tsx`에 연결했다.
- `features/auth/hooks/use-logout.ts`, `features/auth/services/logout-service.ts`, `features/auth/components/auth-action-area.tsx`와 로그인/프로필/로그아웃 버튼 컴포넌트를 추가했다.
- `lib/social-repository/auth-repository.ts`에 `POST /api/auth/logout` 요청과 응답 파서를 추가했다.
- `app/(main)/layout.tsx`에서 `AuthActionArea`를 셸 슬롯으로 주입하고, `features/app-shell/components/main-layout.tsx`는 이를 헤더/사이드바에 배치하도록 조정했다.
- `components/layout/desktop-sidebar.tsx`, `features/app-shell/hooks/use-app-shell.ts`, `features/app-shell/services/shell-service.ts`, `types/app-shell.ts`, `types/auth.ts`를 수정해 세션 사용자와 셸 액션 영역을 함께 다루도록 정리했다.

### 검증
- `npm run lint`
- `npm test`
- `npm run build`

### 결과 또는 기대 효과
- 메인 셸에서 현재 세션 상태에 따라 로그인 버튼 또는 프로필/로그아웃 버튼이 전환된다.
- 로그아웃 성공 시 전역 세션 사용자 상태를 비우고 `/login`으로 이동하는 흐름이 컴포넌트 밖 계층까지 분리되었다.
- 이후 세션 가드와 실제 서버 세션 구현이 붙더라도 현재 셸 액션 영역을 유지한 채 확장할 수 있게 되었다.

### 남은 이슈
- 현재 `SessionProvider`는 실제 서버 세션 대신 프리뷰 사용자 `preview-user`를 초기값으로 사용한다.
- `/api/auth/logout`과 실제 세션 helper가 아직 없어서, 현재 로그아웃 성공은 서버 응답이 붙기 전까지 클라이언트 전역 상태 초기화와 라우팅 흐름 준비 단계에 머문다.
- 보호 라우트 차단과 로그인 페이지 재진입 제어는 `09-session-guard-navigation.md` 단계에서 별도로 붙어야 한다.

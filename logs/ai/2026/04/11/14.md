## 작업: 회원가입 명세 기반 컴포넌트 구현

### 작업 시각
- 2026-04-11 14:04

### 요청 요약
- `docs/ai/README.md`와 베이스 에이전트 규칙을 따르면서 `docs/plan/function/mvp-1/01-signup.md` 명세 기반으로 회원가입 기능 컴포넌트를 구현한다.

### 합의된 범위
- `SignupForm`을 명세형 상태 기반 컴포넌트로 교체한다.
- 회원가입 필드/버튼/에러 컴포넌트, `useSignup`, `signupService`, validator, repository, 공통 타입 계약을 추가한다.
- 기존 인증 레이아웃 구조와 현재 디자인 시스템 프리뷰가 깨지지 않도록 최소 범위로 연결한다.

### 반영 내용
- `features/auth/components/signup-form.tsx`를 정적 프리뷰 폼에서 `useSignup()` 기반의 실제 상태형 폼으로 교체했다.
- `UsernameInputField`, `EmailInputField`, `PasswordInputField`, `ConfirmPasswordInputField`, `SignupSubmitButton`, `SignupErrorMessage`를 `features/auth/components`에 추가해 명세의 컴포넌트 구조를 맞췄다.
- `features/auth/hooks/use-signup.ts`를 추가해 입력값, 실시간 검증 메시지, 제출 상태, 회원가입 결과 상태를 관리하도록 구현했다.
- `features/auth/services/signup-service.ts`, `lib/validators/auth.ts`, `lib/social-repository/auth-repository.ts`, `types/auth.ts`를 추가해 훅 -> 서비스 -> 레포지토리 흐름과 타입 계약을 분리했다.
- `features/design-system/components/design-system-showcase.tsx`의 `SignupForm` 사용부를 현재 인터랙티브 폼 구조에 맞게 최소 수정했다.

### 검증
- `npm run lint`
- `npm run build`

### 결과 또는 기대 효과
- `/signup` 경로가 더 이상 플레이스홀더가 아니라 명세에 맞는 실제 입력/검증/제출 구조를 가진 회원가입 폼을 렌더링한다.
- 회원가입 관련 검증 규칙과 API 호출 경계가 컴포넌트에서 분리되어 이후 세션 저장, 서버 액션, API 연동 단계로 확장하기 쉬워졌다.
- 현재 서버 API가 없는 상태에서도 네트워크 실패를 사용자 메시지로 처리하도록 준비되었다.

### 남은 이슈
- `/api/auth/signup` 서버 구현과 세션 저장 로직은 아직 없으므로 성공 후 자동 로그인 연결은 후속 작업이 필요하다.
- 기존 워크트리에 있던 `README.md`, `package.json`, `scripts/` 변경은 이번 범위와 무관해 그대로 유지했다.
